Havilah Pro - Full Project Report

Chapter 4 — Implementation

4.1 Introduction to Implementation

The implementation phase of the Havilah Pro project marks the translation of system design into a functional, highly responsive, and robust web application. This phase involved setting up the development environment, configuring the core tech stack, and methodically building the UI components and API routes required to satisfy the business logic.

4.2 Environment Setup

The development environment was orchestrated using Node.js as the primary runtime environment. The Next.js framework (Version 14.2.5) was initialized using the create-next-app utility, specifically opting into the modern App Router architecture which provides enhanced nested routing and layout capabilities over the legacy Pages router. TypeScript was enforced across the entire repository to provide strict static typing, catching potential runtime errors during compilation. Tailwind CSS was configured via PostCSS to handle all styling through utility classes, eliminating the need for bulky, external CSS stylesheets.

4.3 Frontend Architecture Implementation

The user interface was constructed using React 18 functional components. A modular, component-driven approach was utilized. Reusable components such as Navbars, Footers, and standard Buttons were isolated into a dedicated `src/components` directory, allowing for clean inclusion across multiple Next.js page routes.

State Management: Context API was utilized to manage global states that required application-wide access. Specifically, a `ThemeContext` was implemented to manage light/dark mode toggles, dynamically injecting Tailwind dark mode classes into the root HTML element. A `LanguageContext` was similarly implemented to trigger the Google Translate Widget conditionally based on user preference.

Animations: To achieve the requested "cinematic" and premium aesthetic, Framer Motion was deeply integrated. Scroll-linked animations were applied to page sections, utilizing `initial`, `whileInView`, and `viewport` props to trigger fade-ins and Y-axis translations only when components entered the user's viewport, minimizing unnecessary DOM recalculations.

4.4 Backend & API Implementation

Because the Havilah platform is primarily an inquiry generation and portfolio showcase tool, a traditional persistent database (such as PostgreSQL or MongoDB) was deemed structurally unnecessary, enhancing security and reducing latency. Instead, a serverless, stateless API architecture was implemented.

Using Next.js Route Handlers (`route.ts`), dedicated API endpoints were created for `/api/contact`, `/api/appointments`, and `/api/internships`. These endpoints operate strictly on the server-side, ensuring that sensitive environment variables (like API keys) are never exposed to the client browser.

Resend Integration: The Resend Email Node.js SDK was implemented within these API routes. When a user submits a form on the frontend, the React component serializes the payload into a JSON object and POSTs it to the Next.js API. The API validates the presence of required fields, formats an HTML email string, and dispatches the payload to the Resend API, which delivers the inquiry directly to the administrative inbox. Try-catch blocks ensure that any failure in the Resend pipeline is caught, propagating a 500 status code back to the client so a failure toast notification can be rendered.

4.5 Deployment Implementation

The application is designed for Edge deployment on platforms like Vercel or Hostinger. The `next.config.mjs` and `package.json` were optimized to utilize the `next build` pipeline, which aggressively statically generates (SSG) the portfolio and marketing pages into raw HTML/CSS at build time, significantly lowering Time to First Byte (TTFB) in production.

Contact API Route (src/app/api/contact/route.ts)

import { NextResponse } from "next/server";
import { Resend } from "resend";
import ContactEmail from "@/emails/ContactEmail";
import { render } from "@react-email/components";

// Initialize Resend
// Note: You must add RESEND_API_KEY to your .env.local file
const resend = new Resend(process.env.RESEND_API_KEY || "re_dummy");

export async function POST(req: Request) {
  try {
    const body = await req.json();
    const { name, email, phone, service, subService, budget, message } = body;

    // Validate minimum required fields
    if (!name || !email || !message) {
      return NextResponse.json(
        { success: false, error: "Name, email, and message are required." },
        { status: 400 }
      );
    }

    if (!process.env.RESEND_API_KEY) {
      console.warn("RESEND_API_KEY is not set. Simulating success.");
      return NextResponse.json({ success: true, simulated: true });
    }

    // Send the email
    const html = await render(ContactEmail({
      name,
      email,
      phone,
      service,
      subService,
      budget,
      message,
    }));

    const resendApiKey = process.env.RESEND_API_KEY as string;
    const emailPayload = {
      from: process.env.FROM_EMAIL as string,
      to: process.env.CONTACT_EMAIL as string,
      subject: `New Havilah Inquiry: ${service} - ${name}`,
      html: html,
    };

    const res = await fetch("https://api.resend.com/emails", {
      method: "POST",
      headers: {
        "Content-Type": "application/json",
        Authorization: `Bearer ${resendApiKey}`,
      },
      body: JSON.stringify(emailPayload),
    });

    if (!res.ok) {
      const errorText = await res.text();
      console.error("Resend fetch error text:", errorText);
      throw new Error(`Resend API error (${res.status}): ${errorText}`);
    }

    const response = await res.json();
    console.log("Resend response:", response);

    return NextResponse.json({ success: true, data: response });
  } catch (error: any) {
    console.error("Error sending contact email:", error);
    return NextResponse.json(
      { success: false, error: "Failed to send email.", details: error.message },
      { status: 500 }
    );
  }
}

"use client";

import React, { useState, useRef, useEffect } from "react";
import { Bot, X, Send, MessageSquare } from "lucide-react";
import { motion, AnimatePresence } from "framer-motion";

interface Message {
  role: "user" | "assistant";
  text: string;
}

export default function Chatbot() {
  const [isOpen, setIsOpen] = useState(false);
  const [message, setMessage] = useState("");
  const [history, setHistory] = useState<Message[]>([
    { role: "assistant", text: "Welcome to Havilah. Ask me anything about our cinematic productions, services, academy, or internships." }
  ]);
  const [loading, setLoading] = useState(false);

  const scrollRef = useRef<HTMLDivElement>(null);

  useEffect(() => {
    if (scrollRef.current) {
      scrollRef.current.scrollTop = scrollRef.current.scrollHeight;
    }
  }, [history, loading]);

  const handleSend = async (textToSend: string) => {
    if (!textToSend.trim()) return;

    const userMsg: Message = { role: "user", text: textToSend };
    setHistory((prev) => [...prev, userMsg]);
    setMessage("");
    setLoading(true);

    try {
      const chatHistory = history.map((h) => ({
        role: h.role,
        text: h.text,
      }));

      const res = await fetch("/api/chat", {
        method: "POST",
        headers: { "Content-Type": "application/json" },
        body: JSON.stringify({ message: textToSend, history: chatHistory }),
      });

      const data = await res.json();
      const replyMsg: Message = { role: "assistant", text: data.reply || "No response received." };
      setHistory((prev) => [...prev, replyMsg]);
    } catch (err) {
      setHistory((prev) => [
        ...prev,
        { role: "assistant", text: "I'm having trouble connecting to the server. Please try again." }
      ]);
    } finally {
      setLoading(false);
    }
  };

  const suggestions = [
    "Tell me about wedding projects",
    "Explore Academy courses",
    "How to rent soundstages",
  ];

  return (
    <div className="fixed bottom-6 right-6 z-[999]">
      <AnimatePresence>
        {!isOpen && (
          <motion.button
            initial={{ scale: 0.8, opacity: 0 }}
            animate={{ scale: 1, opacity: 1 }}
            exit={{ scale: 0.8, opacity: 0 }}
            onClick={() => setIsOpen(true)}
            aria-label="Toggle Chatbot"
            className="w-14 h-14 rounded-full bg-accent text-background flex items-center justify-center shadow-2xl hover:scale-105 active:scale-95 transition-all duration-300 group"
          >
            <MessageSquare className="w-6 h-6 group-hover:rotate-6 transition-transform" />
          </motion.button>
        )}
      </AnimatePresence>

      <AnimatePresence>
        {isOpen && (
          <motion.div
            initial={{ opacity: 0, y: 50, scale: 0.95 }}
            animate={{ opacity: 1, y: 0, scale: 1 }}
            exit={{ opacity: 0, y: 50, scale: 0.95 }}
            transition={{ duration: 0.3, ease: [0.16, 1, 0.3, 1] }}
            className="w-[360px] sm:w-[400px] h-[500px] rounded-2xl border border-border bg-surface/95 backdrop-blur-xl shadow-2xl overflow-hidden flex flex-col justify-between"
          >
            {/* Header */}

              <div className="flex items-center gap-3">
                <div className="w-8 h-8 rounded-full bg-accent/15 border border-accent flex items-center justify-center text-accent">
                  <Bot className="w-4 h-4" />
                </div>
                <div>

Chapter 7 — Performance, Scalability, and Security

7.1 Performance Optimization

The Havilah application achieves exceptional Lighthouse performance scores through aggressive optimization techniques inherent to the Next.js framework.

  • Image Optimization: All portfolio imagery is passed through the Next.js `<Image>` component. This automatically converts legacy image formats into WebP or AVIF, resizes them based on the client's device width, and implements lazy loading so images below the fold do not block the initial page render.
  • Font Optimization: Google Fonts (Inter and Playfair Display) are optimized using `next/font`. Fonts are downloaded at build time and self-hosted with the static assets, eliminating layout shift (CLS) and preventing secondary network requests to Google servers during page load.
  • Static Site Generation (SSG): Pages like the Home, About, and Services pages contain mostly static content. Next.js pre-renders these pages at build time. When a user requests the page, the server instantly serves the cached HTML, resulting in near-instantaneous load times.

7.2 Scalability

Because Havilah relies on a stateless architecture, its scalability potential is virtually limitless compared to traditional monolithic applications.

  • Stateless Architecture: Without a bottlenecked SQL database connection pool, the application can horizontally scale instantly. Traffic spikes (e.g., during a marketing campaign) are easily handled by the CDN and Edge network since form submissions are offloaded to the robust Resend infrastructure.
  • Modular CSS: Tailwind CSS ensures that the stylesheet scales logarithmically rather than exponentially. As more components are added, Tailwind reuses existing utility classes, keeping the global CSS payload under a few kilobytes regardless of application size.

7.3 Security Measures

Security is maintained by strictly separating client and server environments.

  • Environment Variable Masking: Sensitive API keys (Resend) are only accessible within server-side API Route Handlers. They are never prefixed with `NEXT_PUBLIC_`, guaranteeing they never leak into the client bundle.
  • Cross-Site Scripting (XSS) Prevention: React fundamentally protects against XSS attacks by automatically escaping all string variables embedded in JSX before rendering them to the DOM.
